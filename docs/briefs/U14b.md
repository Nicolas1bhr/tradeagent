   current. At every append and rotation start, if `.new` exists and current does not, complete `.new→current` first;
   if that cannot be done, refuse the append and degrade with the reason, never silently. Seam that throws at the last
   act, then an append; plus a mid-sequence restart.
2. A fifth crash point inside act 1: the carry write opens `log.new` with `FileMode.Create`, emptying an existing `.new`;
   one transient IO error after the open loses the only copy of the unresolved marker, and the retry recomputes the
   carry from the emptied file. Act 1 writes a unique temp with `FileMode.CreateNew`; an existing `.new`/temp is never
   truncated (completed per item 1, or read as part of the snapshot); the retry recomputes from the snapshot taken
   before act 1. Seam that opens then fails + a transient-error retry → marker present in every state; mutant
   `CreateNew` → `Create`.
3. `AdapterTeardown.cs` (~:233): overlapping `Stop()` calls let one finalizer publish `Stopped` while another runs, so

   after the last step of the one teardown; `Started()` refused throughout. Then either write the 300 ms-order test that
   makes the lock on `Running→Stopping` load-bearing, or state in the test why that transition cannot race.
4. `AtasConnector.cs` (~:171): during `AuthGrace` a new peer has no stamped status, so the previous connection's refusal
   stays displayed. Stamp "connecting — waiting for the add-on to authenticate" at accept, counter-stamped newer than
   any marker; grace expiry replaces it with silent/unauthenticated; the hello replaces it with the live row.
5. `_sidecarBytes` counts UTF-16 chars against the byte limit `MaxErrorLogBytes`: count encoded bytes, and give it the

   Delete the dead `AppendDurably`; one comment says which sidecar writes are flushed and why. In `docs/CONTRACTS.md`:
