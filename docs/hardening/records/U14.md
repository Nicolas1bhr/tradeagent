## Why it exists

GitHub CI (windows-latest) on 3931c10 failed one test, `CoidWitnessTests.The_file_is_never_absent_while_it_is_being_rewritten`
("the temporary file was left behind"): a rename of the temp onto `coid-witness.json` had failed under a concurrent
reader on a contended runner. The same commit passed on the ATAS box and on macOS, and the next CI run passed — a
load-dependent race. The builder established from source what that meant: `Save()` retried only `IOException` for 60 ms,
`UnauthorizedAccessException` escaped on the first attempt, `Submitting` swallowed everything (`MarkWriteFailed`), `Place`
wrapped it in `Guard(...)` and continued to ATAS, and **`EnsureLoaded` never read the temp** — so a claim whose rename
failed lived only in a file no reader opened, and the durable answer to "did this product submit this identifier" was NO
for an order handed to ATAS microseconds later. That is the rule-1 defect; the leftover `.tmp` was the symptom.

## What the branch does

**Round 1 (a159bf4).** Rename seam made injectable; retry `IOException` and `UnauthorizedAccessException` (5 attempts,
20/40/60/80 ms — a judgment, ≈200 ms measured per fully refused rewrite against an 8.42 s worst path and the 10 s RPC
deadline); reader prefers a newer parsing temp; `Submitting` returns `bool`; sidecar `coid-witness.errors.log` +
`LastWriteFailure`; the churn test asserts durability (301 records readable) before the `.tmp` check.
**Round 2 (1107712).** The recovery rule is LINEAGE, not time: the envelope carries `generation` and `predecessor`
(FNV-1a 64 fingerprint of the committed bytes — kept over SHA-256 because it authenticates lineage, not authorship, and the
assembly may not gain a dependency, trap 34); a temp with zero records is never adopted (round 1 had let a newer `{}`
shadow a good file and the next save commit the void); per-writer temp names; post-rename read-back compares fingerprints;
`_readFailed` semantics fixed (a truncated temp with no committed file no longer reads `io:ok`); `io:degraded` in the token;
the probe prints the sidecar; the support package collects `bridge/*.errors.log`; **the adapter edit**: `Submitting` moved
above `lock (_gate)` and `Place` throws `AtasRejectedException` ("nothing was submitted") on false;
`BridgeHello.witness_failure` → `AtasHealth.BridgeRow` DEGRADED naming the file; an import route the builder's own sweep
found (mutant A4) closed.
**Round 3 (c167bbf).** No adoption without a committed anchor; `Submitting` restores its pre-attempt snapshot on failure
(`Identified` deliberately does not); compare-and-swap + rebase + lock file for two writers; absent/unreadable read-back →
false; a candidate may never shrink the record set, two rivals → adopt neither; a superseding commit clears
`LastWriteFailure`; rejected candidates reported once and renamed out of the glob, adopted rewrite deleted once committed,
`_degraded` = unresolved failure with a RESOLVED marker; `Trouble` on the wire, `SupportsClientOrderId = false` while set;
`Fingerprint` public and tested for discrimination (the verifier's mutant collapsing FNV to an 8-bit fold had stayed green).
**Round 4 (496e2f5..a8b3fb0, items 1–5 of 6):** **one owner per witness** — the lock is mandatory (cannot acquire →
`Submitting` false, `Trouble` "another writer owns this witness"), a CAS miss is a refusal, `Rebase` removed (§9.10: two
bridges on one pipe is a misconfiguration, trap 35, and multi-writer support was generating its own race surface);
**bridge protocol bumped to 3** (the write-ahead promise changed; an older v2 bridge still sent orders after a failed
rename and omits `witness_failure` — the app now refuses it, by the established mechanism); the sidecar never rations a
safety event (rotates instead; quota applies to warnings/markers); readers never write (adoption/quarantine only by the
owner at startup under the lock; the writer re-reads the sidecar before RESOLVED); the probe treats a sidecar ending in
RESOLVED as historical.
