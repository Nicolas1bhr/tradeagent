### Explicit rulings

(a) The ordinary RPC bound itself is real at shipped values: gate ≤10 s, whole frame ≤30 s, reply ≤10 s. The 55-second shutdown claim is not fully composable: it is an unrelated server constant, total `DisposeAsync` can reach approximately 65 seconds, and the second wait remains bounded, so an uncooperative handler can still be left unsettled. See Finding 3.

(b) `EmergencyGateWait` remains only as historical documentation; executable code uses `EmergencyDeadline`. The free-gate V2 path is fixed, but gate and write do not share one absolute deadline: the write receives an almost-full two-second budget before the gate wait begins. See Finding 1.

(c) Heartbeats alone cannot preserve a dead connection. A merely slow bridge can be dropped if it answers no pending RPC in two seconds. The actual bridge serializes frames around synchronous adapter calls, so a legitimate long synchronous ATAS call is classified as dead. See Findings 2 and 5.

(d) Expected mutating-call transport paths are tri-stated, and read failure produces `PossiblyWritten` with a recovery line naming the id. `PipeClient` as a whole is not exclusively tri-state: `ConnectAsync` and the compatibility `SendAsync` remain throwing APIs, and non-filtered programming/resource exceptions can escape; these are not normal post-order CLI transport paths.

(e) The two tests deleted in `3e241d7` and restored in `0bb3712` are present and meaningful at HEAD: tests/TradeAgent.IntegrationTests/ConnectorSendDeadlineTests.cs:755 exercises the real gateway prerequisite-read path, and :821 exercises the total frame ceiling. Execution is UNVERIFIED because no prebuilt artifacts existed and building would violate the no-file-creation instruction.

FINDING 1 — HIGH — src/TradeAgent.Connectors.Atas/AtasConnector.cs:894 — `EmergencyDeadline` can be spent once waiting for the gate and almost again writing, so the promised two-second end-to-end emergency ceiling is false.

CHECK — Hold `_sendGate` for just under two seconds, then release it with insufficient pipe-buffer capacity for the emergency frame; `frameBudget` was captured before the gate wait and starts against a new clock at line 739, allowing elapsed time to approach four seconds.

FINDING 2 — MED — src/TradeAgent.Connectors.Atas/AtasConnector.cs:959 — Answer-only liveness drops a responsive but legitimately occupied bridge whenever one synchronous ATAS command holds its serialized command loop longer than two seconds.

CHECK — Block an ordinary `BridgeServer.Invoke` synchronously for more than two seconds, enqueue an emergency, and allow no unrelated RPC reply; the emergency frame enters the pipe buffer but `PeerAnsweredSince` is false, so line 970 drops the connection.

FINDING 3 — MED — src/TradeAgent.Gateway/GatewayPipeServer.cs:135 — The 55-second drain is hard-coded independently of the actual connector deadlines, so supported timeout customization can again abandon a DISPATCHING request.

CHECK — Construct `AtasConnector(rpcTimeout: 60s)` with 10-second `WriteTimeout` and 30-second `FrameTimeout`; `WorstCaseOrderPath` becomes 100 seconds while a default `GatewayPipeServer` still drains for 55 seconds. Its total disposal ceiling is also 5+55+5, not 55 seconds.
