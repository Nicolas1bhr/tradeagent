## Why it exists (all proven by executed probes on 283d942)

- A crash after the write-ahead (`DISPATCHING`, `needs_reconciliation=0`) was never swept; authorization read only the
  flag, so trading resumed over a possibly-live order (the box's stranded `lc-walk-001-cancel` was the live example).
- Connector return states not in the mapping became `ACKNOWLEDGED` unflagged; a Modify that returned an unchanged order
  was recorded as applied.
- Exceptions outside the catch taxonomy (JsonException, InvalidOperationException; for cancel/modify even Timeout/OCE)
  left records `DISPATCHING` unflagged, contradicting CONTRACTS.md.
- `OperatorCloseAllAsync` sent market closes with no record: a failed-but-landed close plus a second press sold four
  contracts against a two-contract long.

## What the branch does

**Round 1 (eb1dc74).** Startup sweep: every DISPATCHING record → UNKNOWN + flagged, execution PAUSED; aged DISPATCHING
(30 s bound) counts as unconfirmed work before a restart. Exhaustive return-state mapping (UNKNOWN/DISPATCHING/
unrecognised → SettleUnknown). Catch-all after the wire → UNKNOWN + PAUSED + engineering log; only
`ConnectorRejectedException` settles REJECTED. Emergency controls get write-ahead records with per-press nonces.
**Round 2 (2f69813).** Reconcile a cancel/modify/cancel-all against the order it named (not a synthetic `TA-{requestId}`
the operation never transmitted); pause in memory BEFORE persisting UNKNOWN (a SQLite lock could leave a fresh unflagged
row); close every position even after one fails; count a position closed only when flat and say what remains; hold one
press until it is known to have finished; judge a changed price on the instrument's tick grid; one "unconfirmed work"
query everywhere (Dashboard, Doctor, GatewayHost, status, authorization). 8 new mutants + 9 old all bite.
**Round 3 (1e10660).** Under one written rule — *a request leaves the unconfirmed set only on positive, definite, stable
evidence about its own target; anything else is inconclusive and keeps trading paused*: whole-book lookup by id (the
5-minute `since` window had made an hour-old target "absent" → CANCELLED while WORKING); absence grace at DEFAULT
settings from the operation's dispatch time, only on a provable connector; non-definite target states inconclusive; "did
not land" only after the target is observed unchanged across a settle window; cancel-all judged on the captured set; the
press captures its target set and judges completion by its own records, reconstructed at restart; latch keyed by request
id; modify verdict on-grid within one tick, quantity has an unknowable case; sweep fallback surfaced; per-order settlement
from the platform's answer. 21 mutants killed (two harness defects found by mutation and fixed).

## Codex round 3 (the open list) and the manager's decisions for ROUND 4

Class A — reconciliation still concludes on non-definite evidence: F1 evidence from the WRONG connector
(`req.ConnectorId` never compared with `Connector.Id`; after `SwitchConnectorAsync` an empty book on B settles A's
request CANCELLED); F2 cancel-all with no captured set treats a book of only non-definite orders as clear; F3 `Adopt`
accepts the broker's UNKNOWN as resolved and clears the flag; F4 "held still across grace" is not proof an asynchronous
cancel will never land (and a late account-wide sweep can cancel orders placed after trading resumed); F5 a persist
failure on the DEFINITE settle path bypasses the latch (round 2 fixed only the indefinite path); F6 modify never checks
the returned order IS the target (`ConnectorOrderId`/symbol/account); F7 quantity equality with remaining-quantity
semantics; F8 "within one tick" accepts an UNCHANGED price for a one-tick modify (an ignored ES stop tightening reads as
applied).
Class B — the emergency-press subsystem has outgrown its evidence: F9 cancel-all captures ids but the wire call is an
account-wide sweep; F10 close-all captures a quantity but the wire closes whatever exists; F11 a WORKING/ACK/CANCELLED/
REJECTED close does not pause AI trading while the position is open; F12 a definitely failed close holds the press forever
(same nonce → `TryCreate` finds the terminal row → nothing sent); F13 restart drops a terminal press with a non-flat
position; F14 completion reads the CURRENT account, not the record's.

**Round-4 brief (decided, not yet sent):**
- A: the rule stays; derive it correctly — (a) reconciliation uses only the connector whose id the record carries (a
  record from another connector is inconclusive with the reason "placed on A; connected to B"); (b) a non-definite target
  state is never "clear", with or without a captured set; (c) `Adopt` never treats UNKNOWN as resolved; (d) "held still" is
  NOT a terminal verdict — a cancel/modify whose target is unchanged after grace stays inconclusive until a definite state
  (target terminal, broker refusal, or the card); (e) the latch covers the definite settle path (any persist failure after
  the wire → latch); (f) modify verdict: returned order id == target id, then price ∈ {round-down(request),
  round-up(request)} AND ≠ the pre-modify price when the request differs; quantity only when the SDK contract says what
  `OrderInfo.Quantity` means (document it in `ConnectorSdk/Contracts.cs`), else inconclusive.
- B: **SIMPLIFY — one-shot + pause + human.** A press writes per-target records, sends the wire calls, and from that moment
  trading is paused (the press's records count as unconfirmed work — WORKING closes included) until the owner resolves
  through the card, which shows the outcome per target and the current position; a second press is refused while
  unresolved ("close-all sent at HH:MM; resolve it first"); no retry-with-same-nonce path, no in-memory `OperatorPress` to
  reconstruct — the durable records ARE the press. Cancel-all is sent as per-order cancels of the captured set (no
  account-wide sweep on the wire). Close-all re-reads the position immediately before the wire call and refuses (fresh
  two-press) if it differs from what was captured; the wire call keeps ATAS's own close-position (side chosen by ATAS — the
  sign-convention decision stands). Completion/outcome reads the ACCOUNT stored on the records.
- Then a fresh adversarial verifier + Codex on round 4; the earlier verifier's probes (`PROBE_A/A2/C/E/H/K`) and the
  283d942 probes are the regression set.
