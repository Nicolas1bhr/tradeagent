## UNVERIFIED — read, not run, ranked by how much I would want it settled

1. **The ATAS platform installer is downloaded with no checksum and then run elevated.**
   `Prerequisites.cs:118` calls `Downloader.DownloadAsync(InstallerUrl, installer, progress, ct)` — the overload
   whose `sha256` is optional — and `InstallerUrl` (`:54`) is `https://atas.net/Setup/ATASPlatform.exe`. The
   installer is launched with `RequiresAdmin => true`. The TradeAgent updater refuses outright without a checksum
   (`ResolveChecksumAsync`); this path has no equivalent. TLS is the whole of the integrity story, and the vendor
   publishes no hash, so the fix is a design decision rather than a line.
2. **Whether ATAS actually round-trips finding 4's malformed client order id.** The shape violation is proven;
   what a real broker does with `TA-op-close-<nonce>-ES 12-25 [CME Globex Futures]` — refuse, truncate, or accept —
   can only be settled on the box. CONTRACTS.md already records the 64-character ceiling as "a conservative guess:
   ATAS's real client-order-id limit is NOT VERIFIED".
3. **Finding 1 against a real ATAS bridge.** The 30 s / 50 s arithmetic is re-derived from the shipped constants and
   the behaviour is proven on the fake at 1/1000 scale. That a real bridge does spend 30–50 s in the send gate plus
   frame write is exactly what `WorstCaseOrderPath` asserts, but I did not observe it.
4. **The DISPATCHING → UNKNOWN race between the reconciler and a live dispatcher.** `ReconcileAsync` moves a
   stranded `DISPATCHING` row to `UNKNOWN` → `RECONCILING` while the dispatching handler may still be running;
   the handler's later `Settle` then fails the CAS and is logged `already_settled`, discarding the broker's real
   answer. Read at `TradingGateway.cs:1989-1997` and visible as a side effect in P6b, but not probed on its own.
5. **`OpenPressRow` latches before it writes.** `LatchUnconfirmed(requestId, …)` runs before `TryCreate`
   (`TradingGateway.cs:1570-1591`); if the create throws, the latch names a request id with no row, and
   `ReleaseLatchesTheStoreCanVouchFor` skips ids whose row is missing — so the pause would be unclearable by any
   route except a restart. Fails closed, which is why it is here and not in the table.
6. **`Ops.Order` discloses operator press records to the agent.** `FindOrder` → `gateway.GetRequest(id)` has no
   prefix restriction, so `trade order op-close-<nonce>-ES` returns the operator's own press record. Information
   only — no mutation, and the ids are not guessable — so I did not spend a probe on it.
