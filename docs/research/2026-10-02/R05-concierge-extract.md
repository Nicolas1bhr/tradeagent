# 05 - Concierge papers -> evolving TradeAgent: extraction

Key: ECP = Executable Contract Program v0.1 (read 1990-end plus targeted earlier sections 2, 6, 8, 9, 11-14); UIS = Unbounded Institutional Substrate v0.2 (read 1990-end plus targeted 4, 6A, 6D-6F, 6H-6M, 6P, 7.4-7.8; 6B, 6C, 6G, 6N, 6O only as headings); ARCH = Foundation Architecture and PC = Canonical Product Concept (headings, then memory, enforcement, escalation, shadow review, unknown outcome, learning, consequence-graph sections). Section numbers are theirs.
The papers describe a different product (multi-tenant life admin) as "SHOULD" prose with no implementation behind it. They are ideas here, never authority. I did not verify the external-standard claims in their source ledgers and rely on none.
"TradeAgent today" is judged only from CLAUDE.md, PRINCIPLES.md, the brief and recent commit subjects (no repo code read). "NOT SEEN" means absent from those, not proven absent: verify before building. PRINCIPLES states intent only, so "doctrine" means written, not necessarily implemented.

## 2. Do NOT import (over-engineering for a two-person product)

- Federation, sovereign compounds, cross-compound delegation, SPIFFE/A2A (ECP §19; UIS §21): one owner, one machine; signal providers are data sources, not peers needing sovereignty protocols.
- TLA+/formal models and model-to-code correspondence (ECP §22): disproportionate for two people; table-driven state-machine tests plus the mutants already in use give most of the value.
- Typed attenuation algebra with tri-state contains/intersect, policy-engine adapters (Cedar/OPA/OpenFGA/Biscuit) and differential evaluators (ECP §11.3, §11.10, §23.2): grants here are a few capability flags and numeric ceilings, so a subset check plus min() suffices; keep only "indeterminate is never allow".
- Workload identity, sender-constrained tokens, attestation, confidential compute, SCITT/COSE receipts, SLSA/in-toto provenance (ECP §10, §11.9, §15.5, §16.5, §16.8): in-process minting on one laptop; nobody to bridge trust to.
- Semantic registry, namespaced types, referent/projection ontology and "new foundational dimension" admission (ECP §8, §18.5; UIS §5, §7.7): PRINCIPLES defers broader languages and generic governance until a strategy need is shown.
- The 22-invariant constitution, constitutional-change path, red-team checklist and 56-scenario battery (ECP §6, §21.8, §24, §33): CLAUDE.md's rules plus a few scenario fixtures for the new surfaces are enough.
- Execution-provider matrix (gVisor/Firecracker/WASI) and a many-dimension AssuranceProfile (ECP §15, §26.8): Windows laptop and a non-terminal owner; use what the OS offers, labelled honestly, with a handful of profile fields (row 5).
- Universal taint/information-flow engine and egress authorisation for all derived data (ECP §12.4-12.6; UIS §10): the papers themselves call perfect IFC a fiction; keep only holdout-derivation lineage and the read-plus-egress rule (row 7).
- Organisational substrate, dynamic departments, shadow organisations, manager hierarchies (UIS §18, ARCH §86, PC §23): PRINCIPLES says the models own the organisation; keep only the single veto-only review (row 9).
- Pluggable resource economy, attention accounting, scheduler optimisation (UIS §17, PC §21, ECP OQ-13): AI spend reservations and trial budgets already cover the resources that exist.
- PR-class labels, SBOM/release evidence packages, ADRs and a research ledger with IDs for every external fact (ECP §29, §32, §34): BUILD-STATUS and briefs carry the discipline; use claim cards only where a claim feeds money or evidence (row 11).
- Hash-chained/Merkle/transparency evidence and a root-key recovery ceremony (ECP §16.4, OQ-03, OQ-15): a scanner-only `material` table is adequate; at most an exported checkpoint for rollback detection (row 17).
- Generic consequence graphs (PC §25, ECP §14.11): trading consequence is exposure and margin, which the gateway already computes; use the marginal-exposure preview (row 8).
- "Whole conformance harness before any product runtime" sequencing (ECP §25 P0-P3, §36): the product already runs; import per-surface tripwires only (row 13).

## 3. Synthesis

1. TradeAgent's own doctrine already holds the papers' core properties (UNKNOWN never retried, measurement versus claim, no authority by delegation, advisory limits called advisory), so the papers add mechanisms rather than principles.
2. What they add that PRINCIPLES lacks is the machinery for the self-evolution step it only states as intent: an admission ladder in which maturity is never authority for agent-built adapters and tools, change classes set by consequence rather than diff size, and per-surface DO-NOT-PROCEED tripwires.
3. They also supply cheap invariants aimed at version drift and silent semantic loss in a growing population (authorisation bound to a digest of what is actually executed, required fields that make the runner refuse rather than ignore, paper-to-live as a fresh proposal rather than a state copy) and a vocabulary (enforcement-strength classes, manifests as claims, no implicit union of grants) that makes "claim only what is demonstrated" checkable and gateable.
4. The most useful thing they point at, more than anything in their own text, is that an evolving population will attack the verifier and the data adapters, so canary strategies, a three-time datum model with point-in-time conformance, and lineage-based invalidation of verdicts deserve more weight than any federation, formal-methods or ontology material.
5. Adopt each idea as one narrow control at one boundary with a test that goes red when the control is removed, because these papers are unimplemented prose for a different product and PRINCIPLES' own filter (name the concrete consequence, add the smallest control) is the right one.
